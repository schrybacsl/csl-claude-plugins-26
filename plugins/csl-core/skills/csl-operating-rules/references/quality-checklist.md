# Package-Wide Quality Checklist (every deliverable)

1. Data: pulled this session; pull block recorded; QA scripts run; no number carried from a prior edition.
2. Tiers: every RED/AMBER carries a rule ID from csl-schedule-risk/references/tier-rules.md; ten triggers in csl-operating-rules Section 6 checked.
3. Structure: bottom line first; findings item/tier/exposure/owner/action/date; docket with owners and dates.
4. Provenance: document number, revision, date, prepared by/for, distribution, source note; file named per csl-document-control; properties set.
5. Voice: plain, declarative, attributed positions; client-executive prose without dash constructions; acronyms spelled per page.
6. Brand: csl-brand QA checklist passed; fonts verified; no legacy red; CSL Red only in logo/hairlines.
7. Arithmetic re-run in code; dates checked against a calendar; names checked against Microsoft 365 and csl-people.
8. Privacy and AI Policy: no health, HR, or personal content; disputes as record discrepancies; intake check passed (csl-ai-policy Section 2); no invented facts, `[PLACEHOLDER]` used and listed.
9. Delivery: file + document number + two-sentence summary + next action + QA exceptions; transmittal drafted; snapshot saved; nothing sent without instruction; sourced / inferred / assumed table and named reviewer for anything leaving CSL (csl-ai-policy Sections 4 and 5).
10. High-stakes: independent check pass by a fresh reviewer that did not draft (the independent-reviewer agent in Claude Code, or a second CSL employee).
